## [Unreleased]

### Added

- `feat(PJAN-94)`: add the read-only `pjangler fleet status [--agent <id>] [--domain <domain>] [--live] [--project-registry <path>] [--agent-registry <path>] [--contract <path>] [--deadline-ms <ms>] [--json]`, and expose it to MCP as `pjangler_fleet_status`. Stories 1.2 and 1.3 answer *what the fleet is* and *which build each agent runs*; nothing answered **"is the fleet correct?"** in one invocation. Nine observation domains existed as scattered per-repository audits. One read-only traversal now emits one aggregate plus one stable per-agent record covering all nine — `registry`, `project_binding`, `template_scaffold`, `profile`, `runtime`, `systemd`, `live_process`, `bloodbank`, `release_provenance` — each either observed or carrying an explicit `unobserved`/`unsupported` reason, so a domain can never disappear silently. Seven states under one precedence (`error > unobserved > unsupported > fail > warn > skip > pass`), and two verdicts kept apart: `healthy` (no `fail`, no `error`) from `complete` (no `unobserved`, no collection error, no truncation), plus `fleet_complete` for an unfiltered live run. **Host-scoped rule results are reported once, deduped by rule id, in `data.host`** — never folded into a per-agent record, never a registry-wide claim, and never a reason an agent is unhealthy: that promotion is the category error PJAN-84 fixed, and repeating it fleet-wide would undo it 28 times over. The recipe-owned audit rules feed it as **bounded child processes**, because `runAudit` is synchronous and shells out with `spawnSync` and no timeout, so in process a single hung `systemctl` makes the whole-run deadline and SIGINT unimplementable; each child gets a narrow allowlisted environment carrying no credential, its `auditedAt` is dropped at the boundary, and its owner is resolved in the parent from the rule id. `--live` authorizes exactly that — bounded, read-only host and network observation, because the bmad rule's `npm view` is a real network call — and nothing else: no mutation, no process control, no service change, no board change, no Bloodbank activation, and no systemd/live-process/liveness observer (stories 1.8/1.9/1.10 own those). Filters constrain **collection**: `--domain registry` spawns no audit child and no provenance probe, and `--agent <id>` spawns neither for any other agent. An unhealthy or incomplete fleet is data — exit 0, `ok: true` — and only a command failure is nonzero, including `TIMEOUT` (7) and `CANCELLED` (8) with no surviving child.

- `feat(PJAN-94)`: add the read-only `pjangler fleet provenance [--agent <id>] [--project-registry <path>] [--agent-registry <path>] [--contract <path>] [--deadline-ms <ms>] [--json]`, and expose the whole fleet namespace to MCP as `pjangler_fleet_inventory` and `pjangler_fleet_provenance`. Story 1.2 answers *what the fleet is*; nothing answered *which build each agent actually runs*, and `src/mcp-server.ts` imported nothing from `src/fleet/*`, so an automation client could not read the fleet at all. Provenance pairs every **recorded, pinned or declared** value (`desired`) with its **live** counterpart (`observed`), each side naming its own source, in one of six statuses — `match`, `mismatch`, `dirty`, `missing`, `unsupported`, `unobserved` — with the precedence `unobserved > unsupported > missing > dirty > mismatch > match` applied within a fact, so absence is never a match and cleanliness is always its own fact rather than a modifier on the value beside it. The recorded template gitlink is read with `git ls-files --stage` on the *parent*, which is what makes it structural: no worktree move can make it report the worktree's SHA. It is strictly read-only — every git probe passes `--no-optional-locks`, only `ls-files`/`rev-parse`/`remote get-url`/`status --porcelain` are ever run, the observed `hermes` binary is classified by path and never executed, nothing touches the network, and the probe environment strips `GIT_DIR`/`GIT_WORK_TREE`/`GIT_INDEX_FILE` and the rest of git's repository-redirection variables so ambient state cannot make a probe answer about a different repository. `~/.hermes/fleet.env` is read only through a key-allowlisted reader, so the two live Plane API keys beside the fleet paths never enter memory. Probes are deduped by canonical path, bounded in concurrency, bounded per probe, and bounded by a whole-run deadline; a per-probe timeout downgrades one fact to `unobserved` and the run still succeeds, while a blown whole-run deadline is a command failure (`TIMEOUT`, exit 7) because a truncated provenance report must never be mistaken for a complete one. `SIGINT`/`SIGTERM` and an aborted MCP request both cancel (`CANCELLED`, exit 8) and kill every probe child. `data` carries no timestamp, duration, hostname, or completion ordering, so two runs over identical state are byte-identical — which is what makes the CLI/MCP parity assertion a deep equality rather than a resemblance. Against the live fleet it reports 28 agents and 314 facts: 21 agents carrying no `hermes.git_sha`, 22 running a binary under the retired `~/.hermes/hermes-agent` checkout, and 13 declaring a `hermes.repo` that does not exist. A drifted fleet is data — exit 0, `ok: true`, `data.health.healthy: false` — and `healthy` (drift-free) is reported separately from `complete` (everything that should have been observed was), so a run that could not reach half the fleet never reads as a clean bill. `--contract` and `--deadline-ms` are added to `fleet inventory` on the same terms, and both commands dispatch the same core through two thin adapters.

- `feat(PJAN-92)`: add the read-only `pjangler fleet inventory [--agent <id>] [--project-registry <path>] [--agent-registry <path>] [--json]`. Story 1.1 declared who owns which fleet field; nothing read the two canonical registries and correlated them. The only registry-wide agent enumeration in TypeScript projected 6 of ~43 live per-agent field paths and threw raw `ENOENT` on a missing file, and the only registry-wide correlation made network calls and could write — so no invocation could answer "what is the whole fleet, and where does it disagree with itself?". Inventory owns its own tolerant `YAML.parseDocument` pass over both stores, because `loadProjectRegistry` throws on exactly the duplicate slugs, repo paths, board ids and identifiers this command exists to report. It emits one row per raw agent entry with per-field provenance drawn from the contract's declared authority owners, counts source rows in a separate parse so a row-builder bug shows up as `source_rows != emitted_rows` rather than as an agent that quietly vanished, classifies every declared path with `lstat` without following it, and groups identity conflicts under ids that are stable across runs and across machines. Against the live fleet it reports 28 agents, 19 with no project record, two real conflicts (`automatic-ai` claimed by two agents, board identifier `CANDYS` by two more) and the symlinked profile directories the contract forbids. An unhealthy fleet is data: it exits 0 with `data.health.healthy: false`, because the envelope nulls `data` on `ok: false` and reporting drift as a failure would blank the inventory on exactly the runs that matter. Only a command failure is nonzero.

- `feat(PJAN-92)`: add `contracts/fleet-contract.yaml`, the versioned fleet authority and managed-state contract, plus the read-only `pjangler fleet contract validate [--contract <path>] [--json]`. Nothing in the fleet convergence epic could previously answer "who owns this field": Project Registry and Hermes Agent Registry carry overlapping key paths (`repo_path`/`project_path`, `ticket_provider.identifier`/`plane.identifier`, `role_dir`/`role_dir`) with no declared direction, the unregistered profile-root entries and unattributed Hermes processes have no lifecycle class, and Bloodbank discovery was not separated from Bloodbank execution authority. The contract declares eight authority blocks over real key paths and real store environment keys, six one-directional projections whose `direction` is derived from the two stores rather than trusted as prose, five lifecycle classes, the canonical per-agent gateway plus heartbeat service model with the fleet-shared Bloodbank gateway, a five-state activation ladder gated on a strict default-deny `agents.<id>.bloodbank.enabled` that must be the sole field of its own authority block, and five retired modes carrying their own detection patterns. Validation is staged so each exit code answers one question (2 malformed, 3 missing, 4 stated-but-forbidden, 5 unreadable version, 6 internal), every diagnostic carries a dotted field path, and a field claimed by two authority blocks fails naming both and choosing neither. `x-` extensions round-trip byte-stably and are reported apart from policy.

- `feat(PJAN-71)`: replace the project `status` field with computed temporal activity. `status` read `planned` for 22 of 27 registered projects — including ones with commits the same day — so it never varied and never informed. Activity is derived from git at read time (so it cannot go stale, and no cron walks the registry) across every local branch, remote-tracking branch, tag, linked worktree HEAD, and uncommitted edit; the winning source is reported alongside the age. Detached worktrees are covered deliberately: several live projects have their newest work there, where a `git log -1` on the checked-out branch reports months of false staleness. `project list` now orders by real recency. The stored registry field is intentionally left untouched so existing `--json` consumers and the (unapplied) Postgres schema are unaffected.
- `feat(PJAN-71)`: rebuild the `describe` report as a width-aware, GitHub-CLI-style layout, and add `describe --interactive` — a checklist of fixable parity findings with `space` to toggle and `A` to apply. The picker is hand-rolled because @clack's multiselect hard-binds `a` to toggle-all and its aliases cannot be remapped. Adds ANSI-aware layout primitives (`visibleWidth`, `padVisible`, `truncateVisible`, `wrapVisible`, `terminalWidth`) to `utils/style`.
- `feat(PJAN-71)`: add the `pjangler-prompt` binary — a second, project-scoped shell prompt line showing slug, board identifier, and activity age. Bundled as its own entry point (8kb, ~30ms) rather than a subcommand of the CLI (426kb, ~52ms), because it runs on every prompt.
- `feat(PJAN-65)`: implement `pjangler describe`, replacing the "coming soon" placeholder with a real report of detected project type, installed subsystems, config files present, and next steps. Subsystem presence is derived from marker files and kept separate from recipe parity, so a subsystem that was never installed reads `absent` instead of `broken`. Fixable parity drift collapses into the single `migrate --all` step that covers exactly that set; manual-only findings stay itemized. `.project.json` wins over the central registry for the board binding, and any disagreement is reported as drift. Adds `--json`, an optional repo argument, and the `pjangler_describe_project` MCP tool.
- `feat(PJAN-57)`: add recipe-owned lifecycle modules and a single validated `RecipeRegistry` with duplicate, dependency, cycle, ordering, init, audit, and migration dispatch coverage.
- `test(PJAN-57)`: add dogfood env/TOML tests and a packed-CLI generated-project lifecycle test covering real Copier rendering, all six supported CLI roots, Git initialization, clean immediate audit, and idempotent re-init/migration.

### Fixed

- `fix(PJAN-94)`: make fleet machine output flush-safe by construction. On Linux `process.stdout` is asynchronous for a pipe, so `process.exit()` discards whatever is still queued — **and still reports exit 0**. Measured on this runtime: a 200 000-character document reached a file complete and a pipe at 131 072 bytes; `project doctor --json` over a 1500-project registry produced 300 218 valid bytes to a file and 131 072 invalid ones through `| cat`. The fleet namespace was correct only because nothing on its path called `process.exit`, a property maintained by a comment. `src/utils/stdout.ts` adds `writeStdout` (an awaited write callback plus `drain`, swallowing only EPIPE) and `exitAfterFlush` (drains stdout **and** stderr, then exits), `fleet cli.ts`'s single writer awaits it, and the `audit` command adopts both — keeping its documented nonzero exit on a drifted repository while removing the truncation, because `fleet status --live` parses that command's stdout and its truncation is now a correctness dependency rather than a latent bug. Proved at 3.7 MB through a real pipe and a `spawn` capture, and at >64 KiB byte-identical across a file, a pty, a shell pipeline and a `spawn`.

- `fix(PJAN-92)`: remove a literal NUL byte from `src/fleet/contract.ts`. It was written as the separator of an internal dedup key, and it made the file binary to every text tool: `file` reported it as `data`, and GNU grep produced no output for it. That last part is the damage — the machine-wide pre-commit and pre-push secret guards scan the unified diff with `grep -E '^\+'`, so a NUL anywhere in that stream leaves the collected lines empty and the tier-1/tier-2 credential scan silently no-ops for the whole commit. Reproduced end to end with an `AKIA`-shaped key beside it. Written as the `\u0000` escape instead (same runtime value), and pinned by a regression that scans every `src/fleet/*.ts` for a raw NUL.
- `fix(PJAN-92)`: harden `fleet contract validate` against the contract files it is advertised to accept. `retired[].detect` patterns are operator input that run against every scalar leaf, and `^(a+)+$` against a 41-character note pinned a core indefinitely — patterns that are overlong or nest a quantifier inside a quantified group are now refused with a diagnostic rather than executed. A YAML alias bomb reached `toJS()` outside the diagnostics pipeline and surfaced as exit 6, the code reserved for defects in this tool, and is now exit 2. Only `retired[].detect` is exempt from the credential and host-path scan now, not the whole `retired` block, which had let a live-shaped key sit in a `reason:` and validate clean. Every string the report prints is bounded, so a control character in a candidate file can no longer reach the terminal raw, and list fields record their clip in `truncated` instead of overflowing the envelope silently.
- `fix(PJAN-92)`: correct three argv and reporting defects in the fleet namespace. `--contract --json` let Commander bind the flag as the path, answering a JSON caller with the ANSI human report; `--help --json` printed usage text and a failure envelope onto one stdout and exited 2 for a request that succeeded; and `next_actions` named the tracked contract even when `--contract` had validated a different file. `redactHome` also missed `/root`, which the contract's own host-path rule has always covered.
- `fix(PJAN-92)`: teach the contract validator the integrity rules it was missing — a projection may no longer reverse another or fork a second source onto one target, the three per-agent unit patterns must stay distinct, the generated profile file may not shadow the operator-owned override SSOT, a profile root must carry `{profile_name}`, retired ids must be unique, and `superseded_by` must resolve to a real block. Adds mutation coverage for the rules that already existed but were only ever exercised against the tracked contract, which satisfies them: deleting the rule left the suite green.
- `fix(PJAN-57)`: preserve foreign mise hook records, comments, additional TOML keys, leave hooks, and non-owned env scripts while replacing only positively owned enter hooks.
- `fix(PJAN-57)`: restore fatal/cancel short-circuiting for Hermes lifecycle init and derive changed-file reports from observed filesystem changes rather than display glyphs.
- `fix(PJAN-57)`: pin fresh initialization to verified `bmad-method@6.11.1-next.1`, model its multi-module project-name behavior hermetically, and gate publication on the real package contract.
