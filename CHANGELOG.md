- `feat(PJAN-110)`: prove canonical systemd topology and service health. `pjangler fleet status --domain systemd` reported every agent `unsupported` (the `unit_topology` deferral): the unit names on an agent's record were the patterns `service_model.per_agent` derives, carried as expectations and never as observations of the user manager. On the live fleet that hid a gateway enabled+active for an agent whose row declares its channels deferred (`pjangler-pm`), a verified-Telegram agent whose gateway is disabled (`drumjangler-pm`), a heartbeat oneshot whose latest result is exit 209 (`automatic-ai-pm`), a deferred agent whose empty delta inherits the fleet base's `platforms.telegram.enabled: true` (`ssbnk-pm`), five heartbeat pairs on disk the registry never recorded, a registered agent with no units at all (`delonet-director`), a retired consumer reference, and a set of unregistered `hermes-*` units nothing reported. A new read-only systemd observer (`src/fleet/systemd.ts`) reports **five observations per registered agent** -- two registry leaves (`agents.{agent_id}.systemd.gateway_unit` for the canonical topology, `.heartbeat_timer` for the row's own field) and three unit leaves (`units.hermes-{agent_id}-gateway.service`, `-heartbeat.timer`, `-heartbeat.service`), all five declared writable under the contract's `systemd_lifecycle` authority so every finding resolves an owner. It **samples the manager, not the agents**: one `is-system-running`, one `list-units`, one `list-unit-files` (fleet scope only), `stabilization.samples` multi-unit `show` calls carrying every unit of interest at once, and one classification `show` only when there is an unregistered unit -- a bounded child count independent of fleet size, with every agent's window the SAME window. The **desired gateway state is derived from the registry's own messaging declaration**, never read back from the unit: a platform whose `provisioning_status` is `verified` makes the gateway `active`, only `deferred_statuses` make it `deferred`, and a row that declares neither is `undeclared` -- so `deferred-but-enabled`, `verified-channel-gateway-disabled`, `platform-enablement-inherited:<platform>` (a deferred platform the profile's delta does not pin false) and `channel-undeclared` are drift rather than alternate healthy modes. The **template's own stability rule is the contract**: a sample set that is not unanimous is `unstable`, a growing `NRestarts` is `crash-looping`, an `activating` gateway is never proven, and `stability.transitions` reports the transition rather than the most favourable sample. Heartbeat health requires a **successful latest tick**, not an active timer: `latest_result` is `success | failed | in-progress | stuck | never | unknown` and `tick` is `current | overdue | never | unknown`, both BUCKETS compared against `process.hrtime.bigint()` (CLOCK_MONOTONIC, the same clock systemd's `*USecMonotonic` properties use) so no timestamp, age, pid or duration reaches `data`. The role's `role.yaml` reconcile policy and its `runtime/continuous-ticket-sentinel-state.json` are read for their DECLARATION and the PRESENCE of two keys (`checkpoint-only`, `reconcile-opt-out-undeclared`, `reconcile-undeclared`); `runtime/.env`, `auth.json`, logs and 1Password are never opened. A third host finding reports the manager itself in EVERY scope; an unavailable or timed-out manager makes every selected agent's five leaves `error` and samples nothing, and `degraded` is an **available** manager. The observer is **read-only structurally**: the only verbs it can spawn are `is-system-running`, `list-units`, `list-unit-files` and `show` (`systemctlArgv` refuses anything else), nothing is written under `$XDG_CONFIG_HOME/systemd/user`, and every child receives an ALLOWLISTED environment (`service_manifest.probe.env_allowlist` plus `LC_ALL=C` and three `SYSTEMD_*` pins) rather than a copy of this process's. - `feat(PJAN-96)`: make partial fleet health truthful and actionable. Story 1.4 reported *what* every domain observed and could not say whether the answer was **trustworthy** or **actionable**: `health.healthy` is `fail === 0 && error === 0`, so a default run over a fleet where three of nine domains have no observer at all and every audit-fed domain is `unobserved` still read `healthy: true` -- and nothing declared which gaps were AUTHORIZED, because the three `unsupported` literals in `src/fleet/status.ts` authorized themselves. A new evaluator, `src/fleet/health.ts`, classifies every observation on **four separate axes** -- `state` (what was concluded), `applicability` (`required`/`optional`/`not_applicable`/`deferred`/`exception`), `evidence` (`direct`/`declared`/`derived`/`absent`) and `freshness` (`current`/`stale`/`unknown`/`not_applicable`) -- because one word cannot carry four questions and collapsing any two of them is how "we did not look" becomes "it is fine". `evidence: "declared"` is the load-bearing one: a registry field that asserts something with nothing verifying it may be `pass` on its own record but can never set `lifecycle.capability_readiness: "ready"` and never contributes to `proven`. Freshness is emitted as a **bucket and never as an age**, from a reference instant captured once per run and never serialized, so `data` stays byte-identical across two runs. The tracked contract grows an optional `health_policy` root block (`schema_version` 2, `contract_version` 1.1.0; schema 1 still loads) declaring `required_domains`, `deferred_capabilities`, `allowed_warnings`, `allowed_skips` and `freshness` -- **the only thing that can justify a skip, a warning, a deferred capability or a managed exception**, with a new `validateHealthPolicy` stage refusing an unknown domain, a non-positive `max_age_days`, a deferral with no owning story, or a field no authority declares. An authorized gap is still reported, with its own state and a `justification.policy` naming the contract entry; a contract with no block at all authorizes nothing and raises one `health-policy-undeclared` finding rather than failing the run; `health.unjustified` counts the three states a policy can actually authorize -- `warn`, `skip` and `unsupported` -- because a `fail` is not something an entry may excuse and an `unobserved` is a coverage question `complete` already answers. `health.healthy` and `health.complete` keep exactly the meanings story 1.4 pinned -- `complete` gains one conjunct, `contradictions === 0`, which can only make it falser -- and a three-way `health.verdict` (`healthy`/`unhealthy`/`unproven`) is added BESIDE them, derived as `!healthy -> unhealthy : !complete || stale || freshness_unknown || unjustified -> unproven : healthy`, with `health.proven` true only for a fleet-complete healthy run. Every non-pass observation and host finding now carries an `owner`, an `observed`/`desired` pair, a `severity` (`state` x `applicability`), a `repair` class and one exact `next_action`, each derived from a real field -- the audit rule's own `fixable`, its `rule_scope`, and the contract's `activation.execution_authority` -- never from prose: a fixable project rule yields the exact `pjangler migrate <rule_id> <repo> --dry-run`, a host-scoped rule routes to the host, a contract-declared deferral is `blocked` and names its owning story, and anything touching the strict default-deny activation gate is `approval-gated` with a `next_action_class` of `requires-authorization` that names the authorization in the string itself. `data.findings` is stable-sorted by gating impact, severity, scope, agent, domain and `finding_id` **before every cap**, on both the machine and the human path, so a gating finding at position 26 is no longer silently dropped by the report's cap of 25. `detectContradictions` generalizes the host block's worst-wins accumulator, narrowly: where one source PROVED a failure and another reported a pass for one `(agent, domain, field)`, BOTH readings are kept, the worse one wins the rollup, and one `status-contradiction` finding records the disagreement -- ten on the live fleet, every one reconciled by hand and every one a case where both readings are true, which DW-75 records. Each agent record gains a four-field `lifecycle` (`desired_state`, `observed_state`, `capability_readiness`, `activation`) that can never report an agent as routing-ready or activated in this release, and a `member_class` putting every SELECTED agent in exactly one of six buckets whose counts survive both envelope caps. `--baseline <path>` correlates two runs read-only -- nothing is persisted -- emitting `appeared`/`resolved`/`state_changed`/`severity_changed`/`evidence_changed` transitions joined on stable `finding_id`s, with an unreadable, unparseable, differently-scoped, non-status or self-clipped baseline refused as `INVALID_INPUT` at exit 2 before a single probe spawns -- a document taken over the whole fleet and diffed by a `--agent` run would otherwise report `resolved` for every agent it never collected. `--exit-code` projects `data.health.exit_category` onto process exits 10 (unhealthy) and 11 (unproven) while the envelope stays `ok: true` with complete `data`; the default stays 0 because `fleet status` is an observation command and a permanently-red `mise run fleet:status` teaches an operator to ignore it. Both flags reach the MCP tool, and `data.health.exit_category` is the discriminant an MCP client had no way to read at all. `FleetInventoryRow.classification` is finally typed against `FLEET_CLASSIFICATION_IDS` and resolves `intentionally_unmanaged` for a row whose every identity conflict a contract exception covers (DW-30).

- `feat(PJAN-95)`: add the read-only `pjangler fleet status [--agent <id>] [--domain <domain>] [--live] [--project-registry <path>] [--agent-registry <path>] [--contract <path>] [--deadline-ms <ms>] [--json]`, and expose it to MCP as `pjangler_fleet_status`. Stories 1.2 and 1.3 answer *what the fleet is* and *which build each agent runs*; nothing answered **"is the fleet correct?"** in one invocation. Nine observation domains existed as scattered per-repository audits. One read-only traversal now emits one aggregate plus one stable per-agent record covering all nine — `registry`, `project_binding`, `template_scaffold`, `profile`, `runtime`, `systemd`, `live_process`, `bloodbank`, `release_provenance` — each either observed or carrying an explicit `unobserved`/`unsupported` reason, so a domain can never disappear silently. Seven states under one precedence (`error > unobserved > unsupported > fail > warn > skip > pass`), and two verdicts kept apart: `healthy` (no `fail`, no `error`) from `complete` (no `unobserved`, no collection error, no truncation), plus `fleet_complete` for an unfiltered live run. **Host-scoped rule results are reported once, deduped by rule id, in `data.host`** — never folded into a per-agent record, never a registry-wide claim, and never a reason an agent is unhealthy: that promotion is the category error PJAN-84 fixed, and repeating it fleet-wide would undo it 28 times over. The recipe-owned audit rules feed it as **bounded child processes**, because `runAudit` is synchronous and shells out with `spawnSync` and no timeout, so in process a single hung `systemctl` makes the whole-run deadline and SIGINT unimplementable; each child gets a narrow allowlisted environment carrying no credential, its `auditedAt` is dropped at the boundary, and its owner is resolved in the parent from the rule id. `--live` authorizes exactly that — bounded, read-only host and network observation, because the bmad rule's `npm view` is a real network call — and nothing else: no mutation, no process control, no service change, no board change, no Bloodbank activation, and no systemd/live-process/liveness observer (stories 1.8/1.9/1.10 own those). Filters constrain **collection**: `--domain registry` spawns no audit child and no provenance probe, and `--agent <id>` spawns neither for any other agent. An unhealthy or incomplete fleet is data — exit 0, `ok: true` — and only a command failure is nonzero, including `TIMEOUT` (7) and `CANCELLED` (8) with no surviving child. Bounds clip what the envelope CARRIES and never what it CONCLUDES: every selected agent's observations are counted into `by_state`, `health` and the domain rollups even when the agent cap drops its record or the per-agent cap drops its tail, and a clipped record names a `--domain` retrieval that genuinely narrows. Host-scoped results roll up worst-wins across repositories and record the disagreement, because a `pass` from the first repository must not mask a `fail` from a later one. A registry that declares no agents is a collection error with a finding, never a completely observed healthy fleet.

- `feat(PJAN-94)`: add the read-only `pjangler fleet provenance [--agent <id>] [--project-registry <path>] [--agent-registry <path>] [--contract <path>] [--deadline-ms <ms>] [--json]`, and expose the whole fleet namespace to MCP as `pjangler_fleet_inventory` and `pjangler_fleet_provenance`. Story 1.2 answers *what the fleet is*; nothing answered *which build each agent actually runs*, and `src/mcp-server.ts` imported nothing from `src/fleet/*`, so an automation client could not read the fleet at all. Provenance pairs every **recorded, pinned or declared** value (`desired`) with its **live** counterpart (`observed`), each side naming its own source, in one of six statuses — `match`, `mismatch`, `dirty`, `missing`, `unsupported`, `unobserved` — with the precedence `unobserved > unsupported > missing > dirty > mismatch > match` applied within a fact, so absence is never a match and cleanliness is always its own fact rather than a modifier on the value beside it. The recorded template gitlink is read with `git ls-files --stage` on the *parent*, which is what makes it structural: no worktree move can make it report the worktree's SHA. It is strictly read-only — every git probe passes `--no-optional-locks`, only `ls-files`/`rev-parse`/`remote get-url`/`status --porcelain` are ever run, the observed `hermes` binary is classified by path and never executed, nothing touches the network, and the probe environment strips `GIT_DIR`/`GIT_WORK_TREE`/`GIT_INDEX_FILE` and the rest of git's repository-redirection variables so ambient state cannot make a probe answer about a different repository. `~/.hermes/fleet.env` is read only through a key-allowlisted reader, so the two live Plane API keys beside the fleet paths never enter memory. Probes are deduped by canonical path, bounded in concurrency, bounded per probe, and bounded by a whole-run deadline; a per-probe timeout downgrades one fact to `unobserved` and the run still succeeds, while a blown whole-run deadline is a command failure (`TIMEOUT`, exit 7) because a truncated provenance report must never be mistaken for a complete one. `SIGINT`/`SIGTERM` and an aborted MCP request both cancel (`CANCELLED`, exit 8) and kill every probe child. `data` carries no timestamp, duration, hostname, or completion ordering, so two runs over identical state are byte-identical — which is what makes the CLI/MCP parity assertion a deep equality rather than a resemblance. Against the live fleet it reports 28 agents and 314 facts: 21 agents carrying no `hermes.git_sha`, 22 running a binary under the retired `~/.hermes/hermes-agent` checkout, and 13 declaring a `hermes.repo` that does not exist. A drifted fleet is data — exit 0, `ok: true`, `data.health.healthy: false` — and `healthy` (drift-free) is reported separately from `complete` (everything that should have been observed was), so a run that could not reach half the fleet never reads as a clean bill. `--contract` and `--deadline-ms` are added to `fleet inventory` on the same terms, and both commands dispatch the same core through two thin adapters.
