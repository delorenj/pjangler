# PJAN-107: Plane transition mutation contract

The canonical Plane ticket-provider adapter is owned by Krebs (`krebs/adapters/tp/plane.sh`). Pjangler consumes that adapter; this document and `tests/pjan-107-mutation-contract.mjs` pin its observable transition behavior, not a second implementation. A deployed Hermes PM copy may be an older projection: passing the canonical regression does **not** verify or update that deployed copy.

`transition <issue-id> <normalized-state>` resolves the intended lane, sends **at most one PATCH**, and reads back that exact issue. A PATCH has no version or precondition guard. Repeating it after an ambiguous failure can overwrite another actor's intervening change, even when the second request uses the same body. A 2xx response cannot prove the final state stayed put. A non-2xx or lost transport response may nevertheless follow a successfully applied write. Therefore only a verified, same-issue readback matching the intended state ID (and intended label ID for label transitions), with a sequence ID, permits `ok <sequence>`; an unapplied failure is **not retried**. A 2xx followed by divergent state is a failure, not success. A failed, malformed, wrong-issue, or unverifiable readback is a failure without another PATCH. The legacy mutation retry knobs are not permission to resend; GET rate-limit retries remain a separate read-only policy.

The test stages the canonical adapter bytes under a throwaway `.tp/adapters` tree with a fixture `.project.json`, a fixture key, and a recording `curl` executable on a restricted PATH. Its network calls cannot reach Plane; it asserts exact request URLs/order/count and success/failure text for normal completion, unapplied PATCH, lost response after an applied PATCH, divergent state, and failed or unverifiable readbacks. Run with `node scripts/run-tests.mjs pjan-107 pjan-23 pjan-50` (normal runner typechecks and builds first). `PJ_TICKET_PROVIDER_ADAPTERS` may point at a fetched canonical Krebs adapter directory outside the 33GOD tree; the suite uses the shared resolver and never the PM's installed projection.

This contract does not provide concurrency control or atomic compare-and-swap. It neither repairs/rolls out the live PM adapter nor authorizes live board writes. A future guarded write protocol would be a separate architecture decision, not a retry restoration.
