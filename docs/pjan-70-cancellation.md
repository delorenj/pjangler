# PJAN-70 cancellation candidate (not yet complete)

MCP mutation tools `pjangler_migrate_project`, `pjangler_bootstrap_33god_project`, `pjangler_project_init`, and `pjangler_run_recipe` accept `timeoutMs` as a **whole-operation deadline in milliseconds**: default **120000 ms**, minimum **1 ms**, maximum **600000 ms**. The SDK request abort signal is captured before handler work; an already-aborted request does not enter its handler. `LifecycleContext.signal` and `LifecycleContext.deadlineMs` carry the same operation into recipe dispatch. Nested children inherit the remaining deadline, not a new 120000 ms allocation. Cancellation reports `MCP operation cancelled`; expiry reports `MCP operation deadline-exceeded`, both with `isError: true`.

`runChild` starts subprocesses asynchronously in a separate POSIX process group (`detached: true`, `shell: false`). On stop it sends SIGTERM to the group, waits **500 ms** for graceful cleanup, then SIGKILL; after group escalation it waits **100 ms** before settling. Child stdout/stderr collection is bounded to **16777216 bytes** combined. A leader exiting does not cancel escalation of its group. Windows has no POSIX group guarantee; this implementation requires a separate Windows tree-kill strategy before claiming Windows parity.

## Covered and uncovered call paths (sync-bypass audit)

Covered: MCP handler -> preflight `preflightBmadLifecycle` -> `runChild` for installer `--version`; MCP project recipe -> `runGit` -> `runChild`; MCP project plan -> `executeProjectInitPlan` -> Copier -> `runChild`; generic recipe/registry dispatch checks operation status between phases. CLI paths preserve their existing synchronous behavior.

**This is a partial candidate, not acceptance-complete.** Uncovered MCP-reachable synchronous subprocesses remain: `src/project/index.ts` provider adapter and `operatorDisplayName`, `src/project/registryClient.ts` registry service child, `src/parity/rules.ts` BMAD installation/dist-tags/git-ignore/px/provider smoke helpers, `src/parity/skill-roots.ts` git index helpers, `src/notebook/{hooks,checks,overview,git-evidence,entropy}.ts`, `src/bmad/{companion,update-scope}.ts`, `src/describe/activity.ts` git, and `src/project/boardQuery.ts` op read. `preflightMcpLifecycle` itself is filesystem-only. Some direct filesystem writers inside parity checks may run after an asynchronous cancellation unless every rule guards before each write; no whole-operation rollback is provided. The production registry-service helper also needs an async cancellation-aware replacement before this candidate is safe to merge. Tests only cover isolated process-group behavior and existing MCP regressions, not every catalog call path or MCP protocol cancellation. Do not treat this branch as ready for integration.
