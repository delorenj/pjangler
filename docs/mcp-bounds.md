# PJAN-69 — MCP bounded collections

`pjangler_project_list` and `pjangler_audit_project` accept optional `limit` (positive integer, default 100, maximum 500) and opaque `cursor`. Invalid limits fail MCP input validation; invalid or stale cursors return an explicit error. The response's `page` object contains `limit`, `truncated`, `omittedCount`, and `nextCursor` only when another page exists. `omittedCount` is the number of records **after the returned page** (not the number of bytes or records truncated within a record). A page shortened by the byte budget resumes at the **first unreturned record**, not at the requested limit. A record too large to fit by itself fails explicitly rather than yielding a repeating empty page.

Registry projects are sorted by slug using JavaScript code-point comparison; `slugs` is the authoritative ordered sequence for each page and `projects[slug]` is the corresponding record. JSON object key enumeration places integer-index keys first regardless of insertion order, so consumers must traverse `slugs` rather than `Object.keys(projects)`. Audit findings are sorted by rule id with original registration index as the stable tie-breaker. A cursor binds its offset to a digest of the ordered records/findings. An unchanged dataset returns the same records at the same cursor and traverses each exactly once. Changed datasets invalidate prior cursors. Audit `auditedAt` is the time of each fresh audit and can differ across repeated requests even when the findings and page are identical. The audit `summary` is calculated from **this page's** findings; `ok` and `hostOk` still describe the full audit. Registry list projects and audit findings keep their PJAN-68 per-record schemas.

The *entire JSON serialization* of `structuredContent`, including `page` and the rest of the envelope, is capped at 256 KiB UTF-8. JSON escapes count toward this budget. Recipe logs and errors share the serialized-byte allowance remaining after measuring the actual recipe, target directory, status, and worst-case capture counters (with space for array delimiters), in addition to independent 64 KiB raw UTF-8 caps. This prevents a completed apply from being reported as a budget error solely because metadata exceeds a fixed reserve. The readable text is produced from admitted records only and is independently limited to 256 KiB (including formatted `json=false` audit). Handler error text is UTF-8-safe truncated with an explicit marker at 256 KiB, including echoed user input. Other MCP tools use the same 256 KiB envelope guard and fail explicitly if their indivisible response is too large; this does not change CLI output or registry persistence.

`pjangler_run_recipe` uses a shared per-invocation bounded collector during ingredient/check execution: logs and errors each retain at most 64 KiB UTF-8 independently. `capture.logs` and `capture.errors` report `retainedBytes` and `omittedCount` (number of messages or message fragments whose suffix was discarded). No truncated suffix is accumulated by the MCP recipe collector. Failed recipes remain `success=false` and MCP `isError=true`; successful previews and applies remain successful. This capture boundary is MCP-specific, not a change to CLI defaults. A producer's single command result, parity finding, or external tool may allocate before it hands a message to the collector; limiting those producers and process runners is outside PJAN-69.

## Verification (PJAN-69 review repair)

Run from the PJAN-69 worktree after `npm run build` and `npm run typecheck`:

```sh
node scripts/run-tests.mjs pjan-69-mcp-bounds mcp-server-regressions mcp-catalog-regressions pjan-57-lifecycle-recipes-regressions pjan-65-regressions pjan-67-lifecycle-preflight-regressions pjan-67-regressions pjan-67-trusted-lifecycle-regressions
```

The real stdio MCP client in `tests/pjan-69-mcp-bounds.mjs` verifies the default/maximum/invalid limits, cursor traversal and invalidation, byte-shortened registry and audit pages, `json=false` audit, preview/apply and failed recipes, and output schema validation. Its review regressions additionally cover:

- **F1:** mixed integer-index and non-integer slugs at page sizes 1, 2 and 500; `slugs` order and `projects[slug]` identity are checked against the advertised output schema (including a missing-`slugs` negative).
- **F2:** an instrumented recipe ingredient invoked through the real MCP server/client tests 65,451/65,452/65,536-byte ASCII, 20,000 emoji, and 65,536 NUL messages on preview, apply, success and failure. The long existing directory exceeds 3,900 path bytes; a second directory exercises JSON-escaped metadata. Every result checks status, schema, UTF-8 serialized structured/text budgets, capture accounting, and applied file existence.
- **F3:** real client calls cover each handler error branch with long multibyte paths or recipe names where the branch echoes input; all errors are checked for the 256 KiB text limit and valid UTF-8 truncation where applicable. `project_init` may instead fail its indivisible structured envelope budget, and `info`/`project_list` return short errors for these inputs.

The bounded collector producer test in the same suite checks per-channel admission and discarded fragments independently of the serialized client view. No board mutation or main merge is part of this verification.
