> Catalog of the tool's addressable "components": recipes, commands, parity rules, and MCP tools. For a CLI this replaces the UI-component inventory.

## Recipes (`recipeRegistry` — `src/recipes/catalog.ts`)

A recipe owns one subsystem's initialization *and* its parity checks. The registry
rejects duplicate recipe/rule ids, unknown dependencies and cycles, and resolves
dependency order. Five of the eight are user-runnable as subsystems (`pj add <name>`
or `pj recipe run <name>`); `bmad`, `notebook` and `project` are composed, not
scaffolded on their own.

| Recipe | Depends on | Ingredient commands | Owns rules |
| --- | --- | --- | --- |
| `mise-op-inject` | — | `WireMiseOpInject` | `secrets.env-op` |
| `mise` | `mise-op-inject` | `AddMiseToml`, `AddDotenv`, `AddMiseTasksStructure`, `AddMiseBaseToml`, `AddMiseBaseScript`, `AddMiseCodegraphScript`, `AddMiseCodegraphWireScript` | `mise.config-root`, `mise.versioning` |
| `agent-hooks` | `mise` | `CopyAgentHooksTree`, `WireMiseAgentHooks` | `skills.project-manifest`, `sot.agent-symlinks` |
| `bmad` | `agent-hooks` | — | `bmad.scaffold`, `bmad.version`, `bmad.cli-roots` |
| `notebook` | — | — | the seven `notebook.*` rules |
| `project` | `mise`, `agent-hooks`, `bmad`, `notebook` | — | `sot.project-json`, `provenance.copier`, `momo-lifecycle-plane`, `board.schema` |
| `docker` | — | `AddDockerfile`, `AddDockerCompose`, `AddDockerignore` | none |
| `node` | — | `NodeCommands` | none |

`pj subsystems` lists what `pj add` accepts: `mise`, `docker`, `node`, `agent-hooks`,
`mise-op-inject`. `src/utils/registry.ts` exposes the same five as `RECIPE_REGISTRY` —
a read-only facade over the identical instances, not a second registry.

## Parity rules

Deterministic, idempotent audit/migrate rules enforcing the 33god project standard.
**There is no central rule table** — each rule is a check on its owning recipe, and
the registry is the only authority on which ones exist. `pj audit` reports status per
rule; `pj audit --rules <comma,separated,ids>` narrows the report, and an unknown id
is an error rather than an empty pass. `pj migrate <rule-id>` (or `--all`) applies
fixes. Audit status ∈ `pass | fail | warn | skip`; migrate status ∈ `applied | noop |
blocked | skipped | partial`. 19 rules are registered:

| Rule id | Title | Enforces |
| --- | --- | --- |
| `secrets.env-op` | `.env.op` + gitignore secrets contract | A nonempty `.env.op`, the managed `materialize-env.sh` hook in `mise.toml`, and `.env` ignored |
| `mise.config-root` | mise config_root + AGENTS link hooks | `mise.toml` with the owned enter hooks and `_.path` entries, preserving complete foreign hook records |
| `mise.versioning` | managed mise versioning block | The managed `mise-versioning` task block + `.mise/scripts/versioning.sh` |
| `skills.project-manifest` | Skillex project skills | The project's Skillex declaration and its activation (see [`skillex-integration.md`](./skillex-integration.md)) |
| `sot.agent-symlinks` | AGENTS/CLAUDE/GEMINI symlink contract | `CLAUDE.md` & `GEMINI.md` are symlinks → `AGENTS.md` (skips if `AGENTS.md` absent) |
| `bmad.scaffold` | BMAD modules/docs scaffold | BMAD `bmm,bmb,cis` installed from source inputs |
| `bmad.version` | BMAD version currency | Installed BMAD matches the `next` channel (npm dist-tags cached <1h; `skip` when offline) |
| `bmad.cli-roots` | Supported BMAD CLI projection roots | Exactly six local CLI projections, `.agents/` canonical, exact cleanup of pjangler's retired `.gitignore` overrides |
| `notebook.configuration` | Notebook configuration | Endpoint, auth name, policy and finite capture limits are valid |
| `notebook.binding` | Notebook binding | The binding carries stable notebook and Overview note IDs |
| `notebook.remote-notebook` | Remote notebook | The observed notebook's stable ID, marker, name and archive state — `skip` when nothing was observed, since no hidden request is made |
| `notebook.overview-note` | Overview note | Overview membership, project ownership, logical ID and descriptor freshness |
| `notebook.skill-installed` | Project Notebook skill | The digest-verified global skill is installed (host-scoped) |
| `notebook.hooks-projected` | Project Notebook hooks | True SessionStart and SessionEnd hook entries are projected once (host-scoped) |
| `notebook.capture-receipts` | Capture receipts | Capture receipts are present and well-formed |
| `sot.project-json` | Canonical `.project.json` | Required keys, correct `repo_path`, `ticket_provider` block (no legacy `board_url`); flags stray `.plane.json` |
| `provenance.copier` | `.copier-answers.yml` provenance + drift report | `.copier-answers.yml` with its overwrite header and `_src_path`, and name/description drift against `.project.json` |
| `momo-lifecycle-plane` | Momo lifecycle-plane readiness profile | The repo can be driven by Momo; opt-in via `pj audit --profile momo-lifecycle-plane` |
| `board.schema` | Board schema | The Plane board's own schema (states, labels, modules). pjangler owns board *identity*; Pilot (`px`) owns board *schema*, and this rule is the seam — audit is `px --dry-run --json`, a pure read |

Every `notebook.*` rule `skip`s when the repo declares no notebook, and
`sot.agent-symlinks` skips without an `AGENTS.md`. A rule carries `scope`:
`project` for everything except `notebook.skill-installed` and
`notebook.hooks-projected`, which are `host`.

The eight employee rules — `hermes.pm-scaffold`, `hermes.untracked-runtimes`,
`systemd.sentinel`, `hermes.runtime-singleton`, `hermes.fleet-config`,
`hermes.delta-list-override`, `hermes.profile-wiring`, `hermes.registry-parity` —
are Flume's, under the same ids: `flume audit` and `flume remediate <finding>`.
`pj audit --rules hermes.pm-scaffold` errors with "Unknown parity rule id(s)".

Get the live list at runtime: `pj audit --json` or MCP `pjangler_list_parity_rules`.

## MCP tools (`src/mcp-server.ts`)

Server `pjangler-mcp`, 12 tools. All reads/plans are safe; writes require explicit
`apply`, external effects require `live: true` plus a positive opt-in. Responses embed
`@33god-projects` skill guidance.

| Tool | Purpose | Safety default |
| --- | --- | --- |
| `pjangler_list_capabilities` | Recipes, commands, parity rules, recommended workflows, skill synergy | read-only |
| `pjangler_list_parity_rules` | Parity rule ids + guidance | read-only |
| `pjangler_audit_project` | Parity audit with summary counts + next actions | read-only |
| `pjangler_migrate_project` | Run one rule or all rules | `dryRun: true` |
| `pjangler_bootstrap_33god_project` | Create a new CommonProject repo | preview; the board needs `live` + opt-in |
| `pjangler_project_init` | Plan/apply registry-backed init | preview; writes need `apply: true` |
| `pjangler_info` | Local manifest, or a case-insensitive `project_id` lookup in the index | read-only |
| `pjangler_project_list` | List registry projects | read-only |
| `pjangler_project_show` | Show one project by slug | read-only |
| `pjangler_describe_project` | Detected type, subsystems, parity counts, next steps — the orientation call | read-only |
| `pjangler_describe_recipe` | Recipe metadata | read-only |
| `pjangler_run_recipe` | Run a non-interactive recipe against an explicit target dir | preview; writes need `apply: true` |

There is no agent-provisioning tool. `flume-mcp` serves `flume_roster`,
`flume_record` and `flume_review`, and is read-only.
