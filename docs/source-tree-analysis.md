## Entry points

Four bundles, one per `package.json` bin:

- **CLI:** `src/index.ts` → `program.parse()` (commander). Binaries `pjangler` / `pj` → `dist/index.js`.
- **MCP:** `src/mcp-server.ts` → `server.connect(new StdioServerTransport())`. Binary `pjangler-mcp` → `dist/mcp-server.js`.
- **Prompt:** `src/prompt.ts` → `pjangler-prompt` → `dist/prompt.js`. Separate on purpose: loading the parity rule set costs ~52ms, which is too much for a shell prompt.
- **Registry service:** `src/project-registry-service.ts` → `dist/project-registry-service.js`, run by the user systemd unit.

**Package root resolution:** `resolvePjanglerRoot()` walks up from the module dir until it finds `package.json` + `templates/commonproject/copier.yml`, so the tool works both from `src/` (dev) and bundled `dist/` (install). It is defined three times — `project/index.ts` exports the copy other modules import; `mcp-server.ts` and `parity/index.ts` keep private ones.

## What is not here

pjangler no longer hires, renders, audits or reconciles agents. `src/fleet/`, `src/commands/hermes/`, `HermesAgentRecipe`, `contracts/fleet-contract.yaml` and the `templates/hermes-agent` submodule are Flume's now, under `flume/packages/flume-hr/`. What remains is the reading side: `pj describe` reports a repo's employees, `pj identity` repairs the board identifiers projected into `~/.hermes/agents-registry.yaml`, and `src/project/boardQuery.ts` falls back to the fleet-shared `~/.hermes/fleet.env` for a Plane key.

## Notable exclusions (`tsconfig.json`)

`agents/`, `dist/`, `node_modules/`, `plugins/`, `templates/`, `worktrees/` are excluded from typechecking. Only `src/**/*.ts` is compiled.
